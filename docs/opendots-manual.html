OpenDots 功能说明与使用手册

一个可自托管的 AI coworker 工作区：让不同职责的 Dot 在文字、网页、电脑、语音和 Slack 之间持续工作，并把结果沉淀为可编辑的 Space 页面。

本文基于当前仓库源码与配置生成。OpenDots 是模板和早期项目，不是开箱即用的托管 SaaS；会话、模型、语音和第三方连接需要自行配置。

Node.js 24React + ViteSQLite 元数据CopilotKit IntelligenceOpenBot Computer

产品概览

OpenDots 把一个个人 AI 工作区拆成三个核心对象：Space 管理文档，Dot 表示有角色和权限的 specialist，Conversation 保存与某个 Dot 的工作上下文。用户可以直接编辑页面，也可以让 Dot 研究、写作、修改页面或操作自己的隔离电脑。

Spaces 与页面

页面库支持搜索、网格/列表视图、嵌套子页面、Markdown 源码和富文本编辑。自动保存带状态提示，修订号检查可避免旧草稿覆盖新内容。

Specialist Dots

每个 Dot 有名称、角色指令、默认 Space、可访问 Space、研究权限、记忆权限和可选学习容器。

联网与工具

Dot 可以通过 Parallel 研究公共网页、调用授权的 MCP Connection，或在人工批准后执行非只读动作。

Computer 与语音

可选 OpenBot computer 为每个 Dot 提供独立浏览器、文件区和 Shell；可选 Realtime 语音沿用同一会话和工具权限。

边界说明：当前实现是 single-owner 工作区，不包含多用户身份、邀请、共享编辑、文件上传或任意交互式页面嵌入。E2B 不是内置 Computer 后端；Computer 当前使用 OpenBot 容器服务。

架构与数据

浏览器 UI→Vite / React :5173→ /apiNode/Hono API :4310
Node Runtime↔CopilotKit Intelligence / Threads↔OpenAI-compatible Model

服务入口位于 src/server/index.ts。开发模式由 concurrently 同时运行 Node API 和 Vite；Vite 的 /api 代理指向 4310。生产构建由 Node 服务在 4310 提供静态文件。

数据存储位置说明
Spaces、页面、Dots、权限、任务、连接配置SQLite，默认 data/opendots.sqlite应用元数据和页面内容。
会话消息、工具调用、运行事件CopilotKit IntelligenceSQLite 不包含完整会话历史；备份需要同时考虑 Intelligence 项目。
Dot computer 文件和浏览器 profileOpenBot 为每个 Dot 管理的容器卷与 Space 页面分离，停止/启动后可保留。

快速启动

1. 安装并运行开发模式

git clone https://github.com/CopilotKit/OpenDots.git
cd OpenDots
npm ci
cp .env.example .env
npm run dev

打开 http://127.0.0.1:5173。开发模式同时启动前端 5173 和 API 4310，终端按 Ctrl+C 会同时停止两者。

2. 接入对话和模型

页面编辑和工作区配置不依赖聊天服务；要让 Dot 回复，需要 Intelligence 项目密钥、模型 API 密钥和模型名：

CPK_INTELLIGENCE_API_KEY=your-project-key
OPENAI_API_KEY=your-model-key
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=your-model-name

Hosted Intelligence 可执行：

npx copilotkit@latest login
npx copilotkit@latest project select

project select 会写入 CPK_INTELLIGENCE_API_KEY。不要在本仓库执行 copilotkit onboard，因为 OpenDots 已经包含 CopilotKit 集成。

3. 生产构建

npm run build
npm start

生产服务默认监听 4310。外部部署需要反向代理、HTTPS 和与域名匹配的 APP_ORIGIN。

Spaces 与页面

  1. 在左侧选择 Space，进入页面库；可搜索标题和正文，切换网格或列表视图。
  2. 点击新建页面，填写标题后使用富文本编辑器；支持标题、列表、任务清单、表格、引用、代码和 Slash Commands。
  3. 编辑会自动保存，也可使用 Cmd/Ctrl+S 立即保存。保存失败时草稿保留在编辑器中，修订冲突不会静默覆盖服务器版本。
  4. 页面可创建子页面、移动、删除或切换 Markdown 源码模式。删除页面时其子页面会上移到被删除页面的父级。
  5. 打开页面对话，可以让有该 Space 权限的 Dot 阅读当前页面并提出修订；先保存手工编辑，再请求 Dot 修改。

页面路由和冲突检查由 src/server/page-routes.ts 与 src/server/pages.ts 实现。

Dots 与文字聊天

创建和配置 Dot

  1. 打开 Dot 设置，填写名称和角色指令，例如“你是一个研究助理，引用来源并明确不确定性”。
  2. 选择它可以访问的 Space，并指定保存页面的默认 Space。
  3. 按需开启研究权限、记忆权限、Computer 能力和连接工具。权限默认应从最小范围开始。
  4. 保存后新建 Conversation；旧会话会保留创建时绑定的 Dot 和 Learning 容器。

发送工作请求

在聊天框描述目标、约束和交付物。Dot 通过 AG-UI 流式返回文本、来源、工具调用和状态。页面上下文会在页面对话中自动附加，但页面内容属于不可信数据，重要修改前应让 Dot 重新读取页面。

先审阅再保存

要求“先给我草稿，不要直接保存”时，Dot 会调用 review_space_page，界面显示 Approve & save / Decline。批准后才写入授权 Space；草稿变化后需要重新审阅。

背景任务

可从会话创建周期性任务。任务会在原始 Conversation 中运行；运行中断不会自动假设成功，需要检查页面和 Computer 操作后显式重试。

联网研究

默认 WEB_SEARCH_PROVIDER=parallel。Dot 可以搜索主题或读取用户提供的公共 URL，结果包含来源链接；轻量匿名额度可用，生产或较高额度可设置 PARALLEL_API_KEY。

模式服务适用场景
parallelParallel MCP主题搜索、提取多个公共来源；不需要本地浏览器 worker。
browser独立 Playwright Chromium 服务只读取指定公共 URL；JavaScript 关闭，私网、认证页和重定向受限。
disabled无研究工具禁用联网研究。

启用 browser 模式：

npx playwright install chromium
npm run browser

或者使用 Compose profile：docker compose --profile browser up --build -d。浏览器服务与 Dot Computer 不同：前者是只读网页抓取，后者是可交互的独立电脑。

Computer 沙箱

OpenDots 当前的 Computer 后端是固定的 OpenBot computer supervisor，不是 E2B。每个 Dot 获得独立的容器、浏览器 profile 和 workspace；OpenDots 不会回退到宿主机 Shell 或文件系统。

启动本地 Computer 服务

# .env 中设置两个不同的 24+ 字符随机密钥
COMPUTER_SUPERVISOR_URL=http://127.0.0.1:4312
COMPUTER_SUPERVISOR_TOKEN=...
COMPUTER_TOKEN=...
COMPUTER_NAMESPACE=opendots

docker compose -f compose.computers.yml build computer-image computer-supervisor
docker compose -f compose.computers.yml up -d computer-supervisor
npm run dev

在 Dot 的 Computer 面板开启 Computer 和所需权限，然后 Start。可用能力包括：

  • 浏览器：navigate、snapshot、screenshot、click、type、scroll。
  • 文件：在 Dot workspace 内列出、读取和写入相对路径。
  • Shell：在该 Dot 容器内执行有时限的命令。
  • 人工接管：owner 暂停 agent 输入后操作浏览器，再释放控制。
隔离边界：默认是普通 Docker 容器，共享宿主机 kernel；COMPUTER_RUNTIME=runsc 只能选择宿主机已经安装的 gVisor，不会自动安装。仓库没有 E2B、Firecracker 或 Kata 的适配器。

MCP Connections

Connections 允许 Dot 使用邮件、日历、GitHub 或自建 MCP 服务。连接配置保存在服务端，工具按 Dot 单独启用。

  • 只读工具可直接执行并返回结果。
  • 写入、发送、删除或其他非只读动作会产生 Approve & run 卡片。
  • 用户拒绝后，Dot 不应通过另一个工具绕过批准。
  • 连接返回的数据应视为不可信输入，不能覆盖系统指令。

连接字段、工具权限和审批路由见 docs/CONNECTIONS.md、src/server/connection-routes.ts。

语音通话

语音使用浏览器 WebRTC 与 Realtime provider 建立连接；计算型工作仍委派给当前 Dot 的 Intelligence Conversation，因此文本和语音可以共享上下文和权限。

VOICE_API_KEY=...
VOICE_MODEL=gpt-realtime-2.1
VOICE_NAME=marin

浏览器需要麦克风权限，公网部署需要 HTTPS。通话界面提供计时、用户/Dot 字幕、麦克风静音、扬声器静音、最小化和挂断；结束后会保存 call receipt。

Slack

Slack 使用 CopilotKit 托管 Channels SDK，不需要在 OpenDots 中另写 webhook 或 Socket Mode 服务。先在同一个 Intelligence 项目创建 managed channel，再在服务器配置：

SLACK_CHANNEL_NAME=opendots
SLACK_TEAM_ID=T...
SLACK_USER_IDS=U...
SLACK_DOT_ID=...

只允许指定 workspace 和 user ID 触发 Dot。安装 bot 后，在它能访问的 Slack 频道中 mention；同一 thread 的后续消息会继续使用同一个 specialist。详见 Slack setup。

Automatic Learning

Automatic Learning 使用 Intelligence 项目中的 Learning container 收集相关会话证据、生成候选技能，并在审阅发布后向新回合交付技能。它不是本地执行沙箱。

  1. 在 Intelligence Learning 中创建合法 ID，例如 research-workflow。
  2. 在 Dot 设置中填写 Learning container ID；可选择 Use published skills。
  3. 只对新创建的 Conversation 生效，旧会话不会追溯加入。
  4. 在 Intelligence 中运行、审阅和发布技能，启用 Skill delivery 后再验证工具调用。

运维与安全

启动、停止、检查

npm run dev

# 构建并启动生产服务
npm run build
npm start

# 健康检查
curl http://127.0.0.1:5173/
curl http://127.0.0.1:4310/api/workspace

反向代理

公网域名必须配置精确的 APP_ORIGIN，并由 HTTPS 反向代理转发到应用。开发模式通常是 Nginx → Vite 5173 → API 4310；生产模lian式可让 Node 4310 同时提供静态页面和 API。

安全要点

  • 外部监听时设置至少 24 字符的 OWNER_TOKEN；不要把 API 直接暴露给互联网。
  • 各类密钥分开生成和保管，不要提交到 Git。
  • Computer 的 Shell 权限只给确有需要的 Dot；容器共享宿主机 kernel，不应视为 VM 级隔离。
  • 为页面、连接结果、Slack 消息和网页内容保留“不可信数据”边界；审批前不要执行外部副作用。
  • 可用 DO_NOT_TRACK=1 或 COPILOTKIT_TELEMETRY_DISABLED=true 关闭遥测。

故障排查

现象检查处理
页面能打开但 Dot 不回复Settings & setup 或 /api/workspace 的 setup.missing补齐 Intelligence key、OPENAI_API_KEY、OPENAI_MODEL，然后重启。
公网访问 403检查 APP_ORIGIN 是否精确匹配 scheme、域名和端口加入实际 HTTP/HTTPS 来源；同时检查 Vite/Nginx 的 Host 白名单。
dist/client 不存在当前是否运行 npm run dev开发模式可忽略；生产模式先执行 npm run build。
研究工具不可用WEB_SEARCH_PROVIDER 与浏览器配置parallel 模式检查模型配置；browser 模式还需 BROWSER_URL 和 BROWSER_SECRET。
Computer unavailableDocker、supervisor health、三个 Computer 环境变量确认 pinned image 已构建、supervisor 已启动，且 Dot 的权限已开启。
页面保存冲突检查页面 revision 和本地草稿保留本地草稿，刷新服务器版本后合并，再重试保存。
语音连接失败Realtime key/model、HTTPS、麦克风权限确认语音 provider 单独可用；OPENAI_BASE_URL 不会改变语音 endpoint。
